===========================================================
A. BACKEND + DB (Docker) — PRIMARY WORKFLOW
===========================================================
Two services, defined in backend/docker-compose.yml:
  - db      Postgres 16, host port 5434 -> container 5432
  - backend FastAPI app, host port 8001 -> container 8000
            built from backend/Dockerfile

EXPOSED ENDPOINTS (on host machine once containers are up):
  - REST API:              http://localhost:8001
  - OpenAPI spec:          http://localhost:8001/openapi.json
  - Request endpoint:      POST http://localhost:8001/request
  - Feedback endpoint:     POST http://localhost:8001/feedback
  - Bandit state:          GET http://localhost:8001/bandit/state
  - Simulate batch:        POST http://localhost:8001/simulate/batch
  - WebSocket (bandit):    ws://localhost:8001/ws/bandit
  - Research dashboard:    http://localhost:3000/research-dashboard.html
                           (or file:///path/to/frontend/public/research-dashboard.html)

On every container start, docker-entrypoint.sh runs `app/scripts/bootstrap.py`
BEFORE uvicorn starts. It is idempotent by design — each prerequisite checks
live state first and skips itself if already satisfied:
  - waits for the DB to accept connections
  - runs `alembic upgrade head` (no-op if already at head)
  - checks provider count == 150 -> reseeds (clearing first) only if not
  - checks Chroma vector count matches provider count -> re-ingests only if not
  - checks the OSM graph cache file exists -> fetches only if missing
You do not need to run migrations/seed/ingest/graph-fetch separately — starting
the containers is enough. On a fresh machine the first boot does real work
(seed, embed, fetch OSM); on a machine that already has this state, it skips
straight through and starts uvicorn in a few seconds.

B. FRONTEND (no Docker) — run locally
===========================================================
Package manager: pnpm
Points at the backend via NEXT_PUBLIC_API_BASE in frontend/.env.local
(already set to http://localhost:8001 to match the Docker backend's mapped port).

CORS is configured in backend/app/api/main.py:
  - allow_origin_regex: http://localhost(:\d+)? — allows Next.js on any localhost port
  - allow_origins: ["null"] — allows file:// access (research-dashboard.html)
This enables the browser-side frontend to call the backend API directly.

C. BACKEND WITHOUT DOCKER (manual, uv-based) — alternative
===========================================================
Use this if you want to run the backend directly on the host instead of in a
container (e.g. for debugging with breakpoints). Requires `db` from section A
still running in Docker (or any reachable Postgres on port 5434).
Package manager: uv (prefix every python invocation with `uv run`)

cd /Users/gimhanrajapaksha/Desktop/projects/employee/backend

uv run uvicorn app.api.main:app --port 8001

NOTES
-------
- ANTHROPIC_API_KEY must be set in backend/.env (gitignored) for the Context
  Agent's LLM classification step to run — without it, ContextAgent fails
  closed to urgency="normal" rather than crashing. docker-compose.yml passes
  this through to the backend container via env_file.
- Model is currently pinned to claude-haiku-4-5 in app/context/llm_client.py
  (MODEL constant) — an explicit low-cost choice, not the skill's Opus-5 default.
- SEED=42 in .env drives all reproducible seeding (providers, simulator RNG,
  evaluation experiments).
- backend/docker-compose.yml overrides DATABASE_URL for the backend container
  to point at db:5432 (the in-network address) even though .env has
  localhost:5434 (the host-side address for section C) — same .env file works
  for both setups.
- Seeding and embedding ingestion are now self-resetting: running the seed or
  ingest script (directly, or via bootstrap) always clears existing rows/
  vectors first, so re-running them can never accumulate duplicates.
